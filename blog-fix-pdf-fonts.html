How to Fix PDF Font Issues in AutoCAD: Why Your Text Becomes Symbols

Updated: March 19, 2026 • By pdf2dxf Team

Converting engineering drawings from PDF to DXF is often a smooth process—until you open the file in AutoCAD and find that your beautiful annotations have turned into a mess of question marks, squares, or weird symbols.

This is one of the most common complaints in the AEC industry. In this guide, we'll explain why this happens and how to fix it once and for all.

1. The "SHX" vs "TrueType" Problem

The root of the problem lies in how AutoCAD handles text. Historically, AutoCAD uses SHX fonts, which are actually defined as collections of vector lines rather than characters. When you export a drawing to PDF, newer versions of AutoCAD try to be "smart" by embedding these SHX fonts as hidden comments.

However, when a standard converter reads that PDF, it doesn't see "Text"; it sees a bunch of tiny lines that look like a letter. The result? A DXF file where the letter "A" is just 3 separate lines, and you can't edit the numerical value of your dimensions.

2. How pdf2dxf.us Solves This

Our conversion engine at pdf2dxf.us uses an advanced OCR (Optical Character Recognition) layer combined with vector path analysis. Instead of just tracing lines, we try to reconstruct the text entities:

  • Character Recognition: We detect common engineering fonts and map them to standard DXF TEXT entities.
  • Scale Awareness: We keep the text size relative to your drawing scale.
  • Layer Integrity: Text is kept on its original layer, so you can toggle annotations on and off easily.

3. AutoCAD Settings You Should Check

If you've converted a file and the text still looks off, check these internal AutoCAD variables:

  • FONTALT: This variable controls the alternative font used when a font file is missing. Set it to simplex.shx or arial.ttf.
  • PDFSHX: When creating PDFs in AutoCAD, set this to 0 to avoid the creation of those annoying "SHX comments" that confuse most converters.

Why PDF Font Encoding Breaks in AutoCAD

When AutoCAD plots a drawing to PDF, text entities go through a two-stage encoding process. First, AutoCAD maps its internal font (SHX, TTF, or BigFont) to a PDF font resource. Second, the PDF renderer encodes each character using the font's internal glyph mapping — which may or may not correspond to standard Unicode code points.

The problem occurs specifically with AutoCAD SHX fonts (simplex.shx, romans.shx, etc.) and custom company fonts. These fonts were designed in the 1980s before Unicode existed, and their glyph-to-character mapping is non-standard. When a PDF reader or converter tries to extract text from these glyphs, it either produces question marks, empty strings, or random Unicode characters because the reverse-mapping table is missing from the PDF file.

Standard TrueType fonts like Arial, Times New Roman, and Calibri embed proper Unicode mapping tables and convert correctly in nearly all cases.

How to Identify Which Fonts Are Causing Problems

In Adobe Acrobat or the free Adobe Reader, open the PDF → File → Properties → Fonts tab. Any font listed as "Type 3" or showing "(Embedded Subset)" without a proper Unicode name is a candidate for text extraction failure. SHX-derived fonts often appear as generic names like "GDT", "Monotxt", or a filename without a recognizable typeface name.

A simpler test: open the PDF, try to select and copy text with Ctrl+A → Ctrl+C, then paste into Notepad. If the pasted result shows garbage characters or nothing at all, text extraction will fail in any converter — not just pdf2dxf.

Fix Method 1 — Re-export from the Source DWG

If you have access to the original DWG file, this is the most reliable fix. Open the DWG in AutoCAD → change all SHX text styles to Arial or another standard TTF font → re-plot to PDF. The resulting PDF will have extractable Unicode text.

To change text styles in AutoCAD: type STYLE → select each text style → change the Font Name from an SHX file to "Arial" (or another TTF) → Apply. Then use PLOT or PUBLISH to create a new PDF.

Fix Method 2 — Use AutoCAD's "Convert to Text" When Importing DXF

When you open a DXF recovered from a PDF with font issues, AutoCAD may prompt you to substitute missing fonts. At this dialog, map the missing font to Arial or Romans. The geometry of the text entity (position, height, rotation) is preserved even when the font mapping fails — only the rendered characters are wrong.

Fix Method 3 — Manual Re-annotation

For drawings where only specific text elements matter (dimension values, grid labels), the fastest approach is often to treat the converted DXF as a geometry base and add new text manually. The structural lines, walls, and grid are correctly converted; only the annotation layer needs to be re-entered. This takes 15–30 minutes for a typical floor plan and produces cleaner results than attempting automated font repair.

What pdf2dxf Does With Unrecognizable Text

When pdf2dxf encounters a text span where PyMuPDF cannot map glyphs to Unicode (common with embedded SHX fonts), it skips that span rather than outputting garbage characters. This means some text entities will be missing from the output rather than present but unreadable — a deliberate choice to keep the DXF clean for the geometry that does convert correctly.

Text that uses standard fonts (Arial, Calibri, Times New Roman, and most system TTF fonts) converts reliably with correct character content, font height, position, and rotation angle.
